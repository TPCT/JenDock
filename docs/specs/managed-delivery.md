# Managed environment delivery

A source validation builds and publishes immutable artifacts without modifying runtime. A managed deployment explicitly captures an existing environment's selected bound services in the same transaction as the source job. It never provisions services. Each selection pins definition, binding, environment revision, effective resource allocation, and the source target fingerprint. Services recorded stopped are retained without replacement; a runtime executor must also observe actual running state before any replacement.

After verified publication, prepare pins an artifact from this exact job for each selected running service's template. It retains the previous and next definitions and images. One durable rollout lease permits execution; expired leases become recovery-required and are never blindly retried. Every mutation requires the live worker lease and a compare-and-swap check on the selected service definition, binding and resource allocation. A changed allocation invalidates execution rather than reverting resource settings.

The executor verifies owned runtime, immutable image, exact effective limits and healthy state before completing each service. Completion stores a new immutable service definition and replacement binding atomically. Partial completion remains explicit; failed or uncertain runtime changes retain evidence and require reconciliation. No automatic rollback success is inferred. Public results expose only service IDs, names and fixed status text, never commands, file paths, provider errors or credentials.

The immutable job recipe uses schema_kind managed-build and embeds the selection as managed_target, so the job fingerprint includes the entire service selection.

APIs: capture/validate_target at enqueue; prepare after publication; claim/authorize_claim/renew_claim for worker fencing; complete_service after runtime verification; rollback_service only after verified old-image restoration; fail for terminal failure/recovery; public for sanitized status; protected_images for retention. Authorization remains the application boundary's responsibility; the runtime executor remains responsible for trusted Docker inspection and serialized host mutation.
